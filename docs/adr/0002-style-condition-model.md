# ADR 0002：样式条件模型

- 状态：已接受（M0 冻结，2026-10-31；M2 条件模型 v1 已实现，2026-10-31）
- 决策者：Kairos 维护者
- 上游：[direction.md](../../direction.md) §2-C/D/E、[plan-1.0.md](../../.lignting/kairos/plan-1.0.md) M2
- 相关：[ADR 0003 类名/manifest 契约](0003-classname-manifest-contract.md)、[ADR 0004 Gradle 插件与 variant](0004-gradle-plugin-artifact-variant.md)、[公共 API](../contracts/public-api.md)

## 背景

Kairos 当前能做的样式条件只有两类：

1. **样式块整体是常量**：`css { ... }` 的所有声明值在编译期可求值，折叠成一个类名；
2. **块内 `if` / `when` 的每个分支都是常量**：编译器枚举组合，为每个组合生成一个类，并生成“选类名”的条件表达式（`KairosIrGenerationExtension` 的 `Eval.Choice`）。一个块最多 8 种组合，超过就报错。

**实现进度（2026-10-31）**：M2 条件模型 v1 已落地——`StyleScope` 提供 `hover`/`focus`/`focusVisible`/`active`/`disabled`/`checked`/`before`/`after`/`media`/`container`/`supports`，条件进入类名身份与 manifest（schema v4），编译器折叠条件块并生成伪类选择器 / at-rule 包裹的规则；运行时 fallback 用同一 `classNameFor` 计算类名。**尚未实现**：轴模型（`MAX_COMBINATIONS = 8` 仍在，但条件组不参与组合枚举）、shorthand/longhand 关系模型、无条件组的覆盖诊断。

这份 ADR 冻结的是**模型**，不是 M2 的具体函数签名；M2 新增的调用形态必须服从这里的三档语义、条件身份与冲突规则。

## 决策

### 1. 三档描述“值从哪来”，条件描述“声明何时生效”

这是最容易混淆的一点，先拆开：

- **三档（降级档位）**：回答同一个样式值由什么决定。
  - **档 ① 编译期定死**：值只依赖可穷举状态（enum 模式轴），每个状态生成静态类；
  - **档 ② 运行时切类名**：值依赖不可穷举输入，但每个分支的值是常量，两个类都在样式表里，运行时只换类名；
  - **档 ③ 变量通道**：值本身在运行时才确定，改写 CSS 自定义属性。
- **条件作用域**：回答声明在什么条件下生效。伪类、伪元素、media、container、`@supports` 都属于这一维，它们**不是三档之一**，也不产生额外的运行时开销。

因此“主题切换”可以是档 ③（颜色走 `var(--x)`），“hover 变色”是条件作用域，不是档 ②；把两者混为一谈会逼出错误的运行时样式系统。

### 2. 三档的不变式

沿用 [direction.md](../../direction.md) §4 契约 3：**档位之间只有优化程度差异，没有行为差异。** 这是“静默降级”合法的唯一依据，任何一档产生不同 DOM/CSS 行为都按缺陷处理。

对当前实现的具体含义：

- 没有编译器插件时，`css {}` 走运行时 fallback：用同一个 `classNameFor` 算出类名并记录到 `KairosRuntimeRegistry`，DOM 上的类名必须与折叠后完全一致；
- 档 ② 的类名仍是编译期常量，条件表达式只选择整串类名，不读取、不拼接样式值；
- 条件必须纯：当前编译器明确拒绝“条件读取样式 lambda 内部局部变量”（错误信息形如 `the condition of a style choice reads a value declared inside the style block`），因为选择表达式会被搬到调用点。

### 3. 条件身份进入类名

冻结规则：**任何影响声明集合的输入都必须进入类身份**，包括 layer、条件上下文和声明本身。2026-10-31 起实现为 `classNameFor(layer, declarations, conditions)`：条件为空时哈希前像与 v1 完全一致（旧类名不变），条件非空时追加 `#c:` + 规范化条件段。

条件上下文由下列原子按固定顺序组成：

| 原子 | 身份形式 | 说明 |
|---|---|---|
| 可穷举变体 | `state:<axis>=<value>` | 一个 enum 模式轴的某个取值 |
| 伪类/伪元素 | `pseudo:<selector>` | 如 `:hover`、`:focus-visible`、`::before` |
| media | `media:<query>` | 规范化空白后的 query |
| container | `container:<name> <query>` | 无名容器使用空 name |
| supports | `supports:<condition>` | 规范化空白后的条件 |

序列化规范：

- 顺序固定为 `state → pseudo → media → container → supports`；同类型多个原子按字典序排列；
- 连续空白折叠为单个空格，去掉首尾空白；
- **无任何条件原子时，条件段为空，不得在类名里留下分隔符**；
- 条件段一旦非空，就参与哈希前像，不许用“同一个类 + 附加选择器规则”的方式绕过。原因有三：提取/去重按类身份做、manifest 需要解释每个类、第三方样式资产合并时无法保证选择器文本一致。

这条规则会改变条件类的类名；由于 M2 仍在 0.x，允许按 [versioning.md](../contracts/versioning.md) 做一次样式契约主版本升级，但必须同时提供迁移说明与新旧映射，不能静默改名。

### 4. 组合代数：用轴和层，不用组合枚举

`MAX_COMBINATIONS = 8` 仍是对“一个块内多个 choice 的笛卡尔积”的硬上限（**轴模型尚未实现**）。v1 的边界是：条件组内部的声明必须是常量，且一个块不能同时含 `when` 条件值与条件组（编译器报错要求拆分）。因此条件组目前不参与组合枚举。轴模型的替代模型：

- **每个模式轴生成一组类**：轴 `A` 有 `A1..An`，就生成 `n` 个类；元素在每轴选一个类；
- **级联顺序固定**：`kairos.reset < kairos.base < kairos.variant < kairos.override`，优先级由层决定，不由书写顺序或类名排序决定；
- **同层冲突是编译错误**：两轴在同一个层写同一个属性且值不同，编译器必须报错，而不是靠样式表里谁在后面；
- **跨层冲突要可解释**：不同层写同一属性时记录到 manifest 的 `conflicts`，`why` 能打印胜负双方与源码位置（当前 CLI 已按 `winnerLayer`/`loserLayer` 实现）；
- **不可达/漏分支/动态值要诊断**：不可达分支当前被跳过，漏分支与动态值当前报 “cannot resolve style block”；M2 要求给出轴名、缺少的取值和修复建议，并在 strict 模式下升级为构建失败。

轴模型不要求把组合数压到 8 以下，而是消除“必须为每个组合生成一个类”的必要性。代价是元素会多挂几个类，CSS 规则数上升；收益是可组合性与可解释性。

### 5. 级联与 CSS 语义

- **层是优先级唯一来源**：同一层内同一属性写两次，当前在 `styles()` 组合时报 `ambiguous composition`，这是必须保留的行为；
- **shorthand/longhand 在 M2 前不做等价合并**：当前只比较 property 字符串，`padding` 与 `padding-top` 被视为两个属性。声明提取只提取完全相同的 `(layer, property, value)`，因此不会错误合并；但在建立属性关系模型之前，禁止扩大提取/合并范围（plan M2 §3 的同一条要求）；
- **第三方未分层 CSS**：`@layer` 之外的作者样式天然高于所有分层样式。Kairos 生成的规则只落在 `kairos.*` 四层里；应用自己的未分层 CSS 覆盖 Kairos 是预期用法，文档必须写清。M2 支持引入外部 `@layer` 和 token，但不得把框架规则散落到未分层区域；
- **条件选择器与层同时出现**时，按“层优先、条件其次”解释；同一层内两个条件选择器命中同一元素同一属性且都生效时，必须能通过 `why` 解释，不能依赖浏览器实现细节。

### 6. 主题 token 与变量通道

当前变量通道是**约定**而不是原语：`blog-backend` 在 `theme.css` 里手写 `--bg`/`--fg` 等变量，Kairos 规则里写 `var(--bg)`，切换主题只改 `<html>` 上的 `dark` 类。没有 `customProperty(...)` 之类的 DSL。

M2 冻结的方向：

- token 的声明与消费不进入类名哈希（值本身是 `var(--x)` 字符串，编译期可见）；
- 主题类不属于“可穷举样式”的优化收益；它的收益来自 CSS 变量继承与一次类名写入；
- 如果后续增加运行时写自定义属性的 API，它属于档 ③，必须复用同一套条件身份与冲突规则，不能另起一套运行时样式系统。

### 7. 当前实现与目标的差距

| 能力 | 当前（0.1.0，2026-10-31） | M2 剩余目标 |
|---|---|---|
| 伪类/伪元素 | ✅ 已进入条件身份与 manifest | — |
| media / container / supports | ✅ 已进入条件身份与 manifest | 轴模型下的组合与覆盖诊断 |
| 组合模型 | 单块最多 8 种组合枚举；条件组不参与组合 | 按轴生成类组，取消 8 上限 |
| 变体轴 | 普通 `when` 返回不同 `css` 块，无轴契约 | 一等变体契约、覆盖诊断 |
| shorthand/longhand | 只比较属性字符串 | 属性关系模型，禁止未证明安全的共享提取 |
| 条件诊断 | 折叠失败报错；`styles()` 降级计数 + strict 升级 | 轴/分支/动态值诊断 |
| 主题 | 手写变量 + 类约定 | token 与外部 `@layer` 支持 |

## 后果

- 正面：条件与三档正交后，M2 可以只做“条件作用域 + 轴模型”，不必先造运行时样式系统；类身份规则一旦落地，第三方样式资产合并才有共同语言。
- 代价：条件进入类名会带来一次类名全量变化；轴模型会让 HTML 上的类数增加；8 上限取消需要新的冲突诊断，否则会把错误从构建期推到视觉层。
- 风险：条件段序列化如果不稳定（空白、顺序），产物确定性会被破坏；因此规范化规则必须由 golden test 锁定（plan M2/M4 门禁）。

## 替代方案

1. **运行时 CSS-in-JS**：能在运行时算任意值，但与“内容进 HTML/CSS”的目标冲突，也失去 CSS 自身的条件与过渡能力；否决。
2. **分析任意 Kotlin 语法来决定可穷举性**：分析面随语法糖膨胀，与“编写舒服”冲突；只保留固定原语与常量分支；否决。
3. **只靠选择器优先级、不做 `@layer`**：优先级会退化为书写顺序，破坏“优先级由层决定”的契约；否决。
4. **保留 8 组合上限，只把上限调大**：组合数仍是指数增长，只是把墙推远；M2 采用轴模型替代；否决继续加数字。
