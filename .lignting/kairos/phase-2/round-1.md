# 方案文档 · kairos · Phase 2 · R1

> 层级：星币
> 上游：../phases.md
> 生成日期：2026-10-29

## 1. 核心目的

P1 证明了"一个样式块能被折叠"。但任何 CSS-in-JS 静态抽取器都能做到这件事，**它不构成身份**。

这一轮要兑现身份：让样式有**类别**（reset / base / variant / override），让组合（base + override）的胜负由一条确定的代数决定，并且让编译器在编译期就把**必输的那条声明删掉**。不做会怎样：Kairos 与 vanilla-extract 的差别就只剩实现语言，且 P3 的封装、P4 的跨模块都会建在一套没有优先级语义的产物上。

## 2. 本轮范围

- 四层：`kairos.reset / kairos.base / kairos.variant / kairos.override`，类名带层标识。
- 组合原语 `styles(a, b, ...)`：跨层高者胜，同层后者胜；败者从类列表里删除并记入报告。
- 运行时兜底只做拼接，靠 CSS 层序得到相同结果——**折叠是优化，不是行为**。
- 产物：CSS 按层分组输出，映射记录每条冲突（胜者/败者/层/位置）。

明确不做：变异体 DSL（用 Kotlin 自身的 if/when）、伪类与媒体查询的层内槽位（留待后续）。

## 3. 依赖闭包结论

| 契约 | 生产方 | 消费方 | 结论 |
|---|---|---|---|
| 层顺序 | 运行时 Layer 枚举 | 编译器 / 产物 / CLI | 由枚举序号唯一决定，任何地方都不得按名字排序 |
| 类名 | 编译器 + 运行时 | 产物 / 反查 / 剪枝 | 类名必须含层，否则同一 (属性,值) 在不同层会共用一个类而无法分组 |
| 冲突记录 | 编译器 | 报告 / 反查 | 记录胜者与败者双方，反查才能双向回答"谁赢了/我输给谁" |

## 4. 改动顺序与步骤

| # | 改动 | 回滚点 | 验证 |
|---|---|---|---|
| S1 | 运行时加 Layer 与分层类名 | 改回单一前缀即可 | gradle :demo:assembleSite |
| S2 | 编译器按层注册规则 | 收集器单点 | CSS 出现四个 layer 块 |

| S5 | CLI merge 按层优先序输出 | 单模块时无影响 | 合并产物层序 reset<base<variant<override |

## 6. 边界情况与失败场景

| 场景 | 预期 | 处理 |
|---|---|---|
| 同层同属性冲突 | 后者胜 | 记录 resolution |
| 兜底路径同层冲突 | 无法静态消解 | 依赖样式表顺序；文档标注限制 |
| 层参数写错 | 视为 base | 解析不到枚举即退回默认层 |
| 合并时按名字排序层 | 会破坏级联 | 已用索引排序；A9 守住 |
