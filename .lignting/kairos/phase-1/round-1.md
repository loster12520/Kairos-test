## 1. 核心目的

把编译期折叠从"**在 IR 里看得到**"推进到"**真的替换掉**"。

这一轮的成败是整条方向的第一次真实往返：如果编译器插件能在一次真实 Kotlin/JS 编译里，把 `css{}` 块读成声明列表、算出原子类名、把调用点替换成字符串常量，并写出确定性的 CSS 产物——那么 [phases.md 第 3 节](../phases.md#3-分阶段详述) 里 P1 的核心验收就有了第一个可观察的证据；如果替换不成立（IR 形状不对、替换时机不对、产物被后端覆盖），方向文档里"编译期静态产物"这条主张就要当场改，而不是拖到 P2。

**不做会怎样**：P2 的穷举变体、P3 的零残留封装、P4 的跨模块聚合，全部建立在"调用点可以被编译器替换成常量"这个前提上。这一轮不证伪它，等于把三层的风险都堆到最后。

## 2. 本轮范围

对应上游阶段：**P1 · 编译期样式折叠（档①可行性证伪）** 的第一个轮次。

**做**：

- 编译器插件：识别样式原语的调用点，读取其 lambda 体内的常量声明，把整块折叠成字符串常量。
- 原子类名：由声明内容确定性哈希得到；**插件侧与运行时侧共用同一份实现**（不重复实现）。
- 编译期产物：`kairos.css`（按确定顺序排列的原子规则）与 `kairos.map.json`（类名 → 声明 → 源码文件）。
- 冒烟验证：用 Node 跑一次产物，确认折叠后的类名与降级版一致。

**明确不做**（防顺手改无关代码）：

- 不做渲染模型选型、不做 HTML 直出（Q14，属 P1 后续轮次）。
- 不做级联代数、不做 `base + variant` 组合、不做 `@layer` 分类（属 P2）。本轮只把全部规则放进一个固定的 layer 占位，满足契约 5。
- 不做变异体 / N 分支原语（属 P2）。
- 不做 Gradle 统一插件、不做开发期热更新（属 P3）。
- 不做行号级反查（IR 阶段拿不到 source manager；本轮只记文件名 + 偏移，行号属 P3）。
- 不改渲染层与页面代码。

## 3. 依赖闭包结论

本轮是**新增**为主，没有删除 / 搬迁，因此不做删除式闭包分析。但有三处"共享契约"必须先查清，否则两侧会漂移：

| 契约 | 生产方 | 消费方 | 结论 |
|---|---|---|---|
| 类名算法（声明内容 → 类名） | 运行时库 | 编译器插件 | 必须**同一份代码**。做法：插件以 JVM 依赖方式引用运行时库的 JVM 产物，直接调用同一个函数，不重写 |
| 声明列表的提取规则 | 编译器插件 | 运行时库 | 插件识别 `StyleScope.declaration(property, value)` 的常量实参；运行时库保证所有上层写法最终都落到这一个函数（本轮只有它一个入口） |
| 产物格式（`kairos.map.json` 的字段） | 编译器插件 | 后续轮次的反查工具（P3） | 本轮定 v1 字段并冻结：`className` / `property` / `value` / `sources[]`；新增字段只能加不能改语义 |

`[事实·依据]` 前置侦察已确认：一次真实 Kotlin/JS 编译里，插件能同时观察到 `dev.kairos.runtime.css`（3 次）与 `dev.kairos.runtime.StyleScope.declaration`（4 次）。

## 4. 改动顺序与步骤

排序判据：**中间态坏得最少**——每一步做完，工程都能构建、都能验证。

| # | 改动内容 | 回滚点 | 验证命令 |
|---|---|---|---|
| S1 | 把类名算法从"运行时私有"提升为"两侧共享"：插件以 JVM 依赖引用运行时库；运行时侧把算法函数暴露为公开 API，并补一组黄金用例（同一批声明 → 一批固定类名） | 删除插件对运行时库的依赖行即可回到"各写一份"（本轮不做这种状态，仅作为回滚兜底） | `gradle :kairos-runtime:jvmTest` |
| S2 | 插件侧新增"声明提取器"：从 `css{}` 调用的 lambda 参数体里，按源码顺序收集 `declaration(prop, value)` 的常量实参；遇到任何非字面量实参即判定为"不可折叠" | 该函数是新增文件，删除即回滚；对外只被折叠步骤调用 | `gradle :kairos-compiler-plugin:test`（新增该提取器的单元测试，直接对 IR 之外的纯数据结构做断言） |
| S3 | 折叠：命中且可折叠时，把 `css{}` 调用替换为字符串常量；不可折叠时原样保留（静默降级，D23） | 关闭折叠只需让插件在上一步判定处直接返回原表达式（保留代码路径） | `gradle :demo:compileKotlinJs` 后扫描产物：折叠前能看到运行时调用，折叠后看不到 |
| S4 | 产物写出：把本轮收集到的规则按类名排序，写出 `kairos.css` 与 `kairos.map.json`；全部包在一个固定 layer 里 | 写出逻辑集中在单个函数，失败不影响编译（仅丢产物） | `gradle :demo:compileKotlinJs` 两次（先删输出目录），比对两份产物的哈希 |
| S5 | 冒烟脚本：Node 跑 `demo` 的 JVM 与 JS 两侧输出，比对"折叠版类名"与"降级版类名"是否逐个相等 | 脚本是新增文件，删除即回滚 | `gradle :demo:jvmRun` / `node <产物>`（真实命令见 §5） |

**不可并行**：S2 依赖 S1（要用共享算法）；S4 依赖 S2/S3（要有规则可写）；S5 依赖全部。

## 5. 验收标准细化

对应上游 [phases.md P1 核心验收标准](../phases.md#p1--编译期样式折叠档可行性证伪) 的展开，**不替换**：

| # | 上游条目 | 可执行条目 | 命令 | 期望结果 |
|---|---|---|---|---|
| A1 | ① 档①成立 | 折叠后产物 JS 中不存在样式原语的运行时调用 | 编译 demo 的 JS 目标后，在产物 JS 中搜索 `kairos` 运行时样式符号 | 0 命中 |
| A2 | ① 档①成立 | 折叠后的类名与运行时降级版逐个相等 | 跑 Node（JS 产物）与 JVM（降级路径）两侧，比对输出 | 两侧字符串完全一致 |
| A3 | ② 产物确定性 | 删除输出目录后连续两次构建，CSS 与映射文件逐字节一致 | 连续两次构建后取 SHA-256 | 两次哈希相等 |
| A4 | ③ 降级不骗人 | 故意写一个捕获运行时值的样式块，其类名与折叠版相同、只在归属上不同 | 同一份声明分别走折叠路径与运行时路径，比对类名 | 类名相等；运行时登记表非空 |
| A5 | 产物可用 | `kairos.css` 能被浏览器解析且规则数等于去重后的声明数 | 用 Node 解析 CSS 文本（数规则条数） | 条数相等 |

## 6. 边界情况与失败场景

| 场景 | 预期行为 | 处理 |
|---|---|---|
| `css{}` 体内出现非字面量实参（捕获运行时变量） | 不折叠，走运行时降级 | 静默（D23），行为与折叠版一致；由 A4 守住 |
| `css{}` 体内出现循环 / 条件 / 局部 val | 本轮判定为不可折叠 | 同上；"可判定子集"的扩张属 P2 |
| 同一组声明在多个位置出现 | 只产出**一条** CSS 规则 | 原子类名由内容哈希决定，天然去重；A3 的顺序保证依赖这一点 |
| 插件在编译期写文件失败（目录不存在 / 无权限） | 不阻断编译，只丢产物 | 插件内 try/catch + 把错误写进报告文件；不允许因产物写出失败而让编译挂掉 |
| 插件因为编译两次（JS / JVM）而重复写同一份产物 | 只有 JS 目标挂插件，JVM 目标不挂 | 由构建配置保证；若将来两侧都挂，产物按目标分目录 |
| Kotlin 编译器插件 API 在升级后不兼容 | 构建失败，且失败点明确 | 本轮锁定 Kotlin 2.2.20；升级验证属 P3 |
