## 1. 核心目的

R1 只证明了"样式块能被编译器折叠"，产物是一串类名与一份 CSS。但 [phases.md 第 3 节](../phases.md#3-分阶段详述) 里 P1 的目标是"**一个能在浏览器打开的静态页面**"——折叠机制成立、产物却不可用，等于只证了一半。

这一轮要证明的是：**折叠出来的类名能被一个真实的页面消费**，而且页面本身是静态的——HTML 在构建期生成，CSS 在编译期生成，运行时只剩两个类名写入。**不做会怎样**：P2 的多轴变体将没有承载页面，无法验证"级联与组合"在真实结构上的表现。

## 2. 本轮范围

**做**：

- 渲染模型选型（Q14）：构建期在 JVM 上把同一份 Kotlin 页面描述渲染成静态 HTML。
- 一个与渲染器无关的节点模型 + 确定性 HTML 序列化（属性顺序、缩进、转义全部固定）。
- demo 页面：一张真实小页面（标题、说明、三张卡片、页脚），带两个交互（主题、密度）。
- 交互只允许写类名：初始主题在构建期定死（档①），运行时切换是一次类名组替换（档②）。
- 产物装配：`index.html` + 编译期 `kairos.css` + 手写 `site.css` + 最小 JS。
- 浏览器级验收：用真实 DOM（jsdom）加载页面、点击、断言"只改类名、不写内联样式"。

**明确不做**：

- 不做 IR 解释器把整棵组件树常量折叠（候选 (c)，成本最高、收益在 P1 阶段不可判）。
- 不做运行时建 DOM（候选 (b)），它与"HTML 直出"直接冲突。
- 不做组件状态管理与重渲染（P2 之后）。
- 不做变异体原语、不做级联代数（P2）。
- 不优化 JS 体积（DCE / 单文件打包属 P3 的开发体验）。

## 3. 依赖闭包结论

| 契约 | 生产方 | 消费方 | 结论 |
|---|---|---|---|
| 节点模型 | 运行时库（common） | JVM 渲染器、页面构造 | 纯数据、无平台 API，两个目标共用同一份 |
| 类名字符串 | JS 侧（折叠）、JVM 侧（运行时降级） | 静态 HTML、事件接线 | 必须逐字符相同——由 R1 的 A2 保证，本轮不再重复验证 |
| HTML 产物确定性 | JVM 渲染器 | 构建期装配 | 属性保持插入顺序，禁止时间戳 / 随机 id |
| CSS 归属 | 编译期 CSS 在 `@layer kairos` 内 | 手写 `site.css`（无 layer） | 手写样式优先于 kairos 层（无 layer 胜过分层），这是有意的：布局归人写，变体归编译器 |

## 4. 改动顺序与步骤

| # | 改动内容 | 回滚点 | 验证命令 |
|---|---|---|---|
| S1 | 节点模型：`Node` / `TextNode` / `ElementNode` + 元素构建器（含文档级 `html`/`head`/`body`） | 新增文件，删除即回滚 | `gradle :kairos-runtime:build` |
| S2 | HTML 序列化：确定性输出，文本叶子单行渲染，转义 `& < > "` | 独立文件，删除即回滚 | `gradle :demo:renderSite` 后比对两次产物 |
| S3 | 页面描述：把样式全部写成 `css { }` 块，用枚举驱动主题与密度变体 | 页面是新增文件；回滚等于回到 R1 的 `Page.kt` | `gradle :demo:assembleSite` |
| S4 | 装配：`renderSite`（JVM 出 HTML）+ 复制编译期 CSS / JS / 手写 CSS 到 `build/site` | 两个 Gradle 任务，移除即回滚 | 目录内 8 个文件齐全 |
| S5 | 事件接线（JS）：两个按钮只做类名组替换；无 DOM 环境下跳过并在 Node 下打印诊断 | 单个文件，删除即回滚 | `node tools/browser-check.mjs` |

**不可并行**：S2 依赖 S1；S3 依赖 S1/S2；S4 依赖 S3 与 JS 编译；S5 独立但对 S4 的产物生效。

## 6. 边界情况与失败场景

| 场景 | 预期行为 | 处理 |
|---|---|---|
| 页面构造里出现不可折叠的 `css { }` | JVM 侧走运行时、JS 侧走折叠，两侧类名仍相同 | R1 的 A4 已守住；本轮不额外处理 |
| 文本包含 `<` `&` 等字符 | 转义后再输出 | 序列化器统一转义；不做可选转义 |
| 元素只有一段文本 | 渲染成单行，不产生三行 `<title>` | 由 S2 的单文本叶子规则保证 |
| 页面在 Node 里被执行（无 DOM） | 跳过事件接线，只打印诊断 | 用 `typeof document` 判定 |
| 手写 CSS 与 kairos 层冲突 | 手写（无 layer）胜出 | 有意为之：布局归人写；P2 做级联时重新审视 |
