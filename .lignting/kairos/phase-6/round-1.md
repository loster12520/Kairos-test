# 方案文档 · kairos · Phase 6 · R1

> 层级：星币
> 上游：../phases.md
> 生成日期：2026-10-30

## 1. 核心目的

P5 把"一个块一个类"做出来了，但立刻暴露了两个新问题：

1. **合并类之间仍有重复声明**：两个块都写 `font-size: 14px` 时，两份 CSS 里各出现一次。用户要的是"提取成独立类 + 元素多挂一个类"。
2. **块内三元表达式被完全禁止**：为了保住"一块一类"，P5 把条件值全推给整组选择。用户要的是 `fontSize(if (big) 20.px else 14.px)` 这类写法也能被优化。

第三个问题是产品性的：博客还停在"能跑"，缺少 Markdown 与全局主题切换——而主题切换正是这套框架最该展示的能力。

## 2. 本轮范围

- **声明提取**：同一编译单元内，出现 ≥2 次的声明被提升为独立类，元素同时携带共享类与残差类。
- **块内三元 / when**：分支全为常量时，编译器枚举组合、为每种组合生成一个类，并生成一个"选类名"的条件表达式。
- **博客完善**：Markdown 渲染（标题/段落/列表/引用/行内格式/链接）、评论 Markdown、新建与详情、深链刷新返回整页。
- **全局亮/暗主题**：颜色走 CSS 变量（档③变量通道），切换只改 `<html>` 的一个类，并持久化。

明确不做：伪类 / 媒体查询原语（下一轮）、跨模块/跨层的声明提取（见 §7）。

## 3. 依赖闭包结论

| 契约 | 生产方 | 消费方 | 结论 |
|---|---|---|---|
| 声明频次 | 编译器第一遍扫描 | 折叠第二遍 | 需要模块级预扫描；单遍折叠拿不到全局知识 |
| 类名 | 运行时 `classNameFor(layer, declarations)` | 编译器 / CLI / 验收 | 共享类是"单声明组"，残差类是"剩余声明组"，同一函数 |
| 条件表达式 | 编译器 | 运行时 | 条件 IR 从 lambda 内取出，必须确认不引用 lambda 局部值，否则拒绝折叠 |
| 主题 | 手写 theme.css（变量） | Kairos 规则（var(...)） | 颜色只在一个地方定义；切换是 `@<html>`@ 的一个类 |

| # | 条目 | 命令 | 期望 |

## 6. 边界情况与失败场景

| 场景 | 预期 | 处理 |
|---|---|---|
| 组合数爆炸 | 拒绝并提示 | 单块最多 8 种组合 |
| 条件引用 lambda 局部值 | 拒绝折叠 | 报告"condition reads a value declared inside the style block" |
| 跨层同值声明 | 不合并 | 层是类身份的一部分，合并会破坏优先级 |
| 跨模块同值声明 | 不合并 | 需要全程序知识；合并后会影响运行时切换的类 |
| 深链刷新 | 返回整页 | 依据 HX-Request 头区分 |

## 7. 与上游的偏离

| # | 上游 | 本层 | 理由 | 建议 |
|---|---|---|---|---|
| 1 | "一个块一个类"（P5） | 改为"共享原子类 + 残差类"两级 | 用户要求消除重复声明 | 建议修订 P5 报告 |
| 2 | 块内不允许动态值（P5） | 允许**全常量分支**的三元/when | 用户要求针对性优化；枚举组合 + 选类名同样零样式计算 | 建议修订 P5 报告 |
| 3 | — | 提取只在**同一编译单元内**生效 | 跨模块/跨层合并需要全程序知识，事后合并对运行时切换的类不安全 | 文档中明确边界 |
