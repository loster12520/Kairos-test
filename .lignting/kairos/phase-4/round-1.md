> 层级：星币
> 上游：../phases.md
> 生成日期：2026-10-29

## 1. 核心目的

方向文档的验证信号 5 是"用 Kairos 写出第二个自己的项目，且不需要改动框架源码"。第二个项目一定会**跨模块**，也一定会**引入不用的东西**。

P1–P3 的产物是"一个模块自己产出 CSS"。没有跨模块聚合，第二个模块的样式根本不会进最终页面；没有剪枝，页面会带着整包原子类上线——两条都会让"静态产物做到极致"这句话落空。

## 2. 本轮范围

- 第二个模块 `demo-feature`：独立编译、独立产物、独立映射。
- 聚合：把多个模块映射合并为一份分层样式表，跨模块按类名去重。
- 剪枝：以"真正发出去的文件"（HTML + JS）为使用集合，删掉没人用的规则。
- 收口：这两步做成构建里的两个任务，而不是手工命令。

明确不做：跨模块的样式树摇（死代码分析）、增量聚合。

## 3. 依赖闭包结论

| 契约 | 生产方 | 消费方 | 结论 |
|---|---|---|---|
| 映射格式 | 各模块编译器 | 合并工具 | 已冻结 v2；合并只依赖 className/layer/layerIndex/property/value |
| 类名唯一性 | 编译器 | 合并 | 类名是内容哈希，跨模块天然去重；冲突意味着哈希碰撞，必须报错 |
| 使用集合 | 产物 HTML/JS | 剪枝 | 折叠后的类名在 JS 里就是字面量，与 HTML 一起扫描即可覆盖动态类 |

## 4. 改动顺序与步骤

| # | 改动 | 回滚点 | 验证 |
|---|---|---|---|
| S1 | 新建 demo-feature 模块并接插件 | 删除模块 | gradle :demo-feature:build 产出三个文件 |
| S2 | demo 依赖 feature 并渲染其面板 | 去掉依赖 | index.html 出现 Build stats |
| S3 | CLI merge 合并多映射 | 独立命令 | 层块顺序与去重正确 |
| S4 | CLI prune 按产物剪枝 | 独立命令 | 输出 kept/dropped |
| S5 | 装配链接入 merge + prune | 去掉两个任务 | gradle :demo:assembleSite 一步产出最终站点 |

## 6. 边界情况与失败场景

| 场景 | 预期 | 处理 |
|---|---|---|
| 两模块对同一类名给出不同声明 | 哈希碰撞 | merge 直接报错退出 |
| 剪枝误删动态类 | 样式丢失 | 使用集合包含 JS 产物（折叠后的类名是字面量）；宁可多留不误删 |
| 层顺序被合并打乱 | 级联失效 | 按 layerIndex 排序；A9 守住 |
